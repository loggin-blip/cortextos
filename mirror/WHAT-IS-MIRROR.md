# What IS Mirror?

## The Problem

Every Claude Code session starts from zero. Max spends 50-200 messages iterating — correcting layouts, rejecting defaults, guiding Claude toward his standards. Next session, same project or new: all that iteration is lost. Claude makes the same mistakes. Max corrects the same things.

One prompt doesn't make us better. 200 prompts should — but today they don't. Each session is transactional. Nothing compounds.

## What Mirror Produces

Mirror's output is NOT a log. NOT a preference list. NOT data points.

Mirror produces five things:

### 1. Process Blueprints
"When Max builds a dashboard, he: (1) defines data model first, (2) builds API routes, (3) creates mobile-first layout skeleton, (4) iterates design until it feels right, (5) polishes with animations last."

One blueprint per project type. Built from observing multiple completed projects.

### 2. Quality Criteria
"Max rejects: generic layouts, placeholder images, unstyled defaults, too many features at once. Max accepts: custom typography, real data, subtle animations, mobile-first responsive."

What "done" looks like. What "not good enough" looks like.

### 3. Decision Heuristics
"When choosing between component libraries, Max picks ones with Tailwind integration, copy-paste paradigm, minimal bundle size. When stuck on layout, Max starts over from mobile view instead of fixing desktop."

Not WHAT Max chose — WHY, and the pattern behind it.

### 4. Anti-Patterns
"Things Claude does that Max always corrects: using default blue, adding unasked features, making navigation too complex, forgetting mobile breakpoints."

The corrections Max shouldn't have to give twice.

### 5. Context Briefs
"Last session (2h): You were building the team schedule page. Rejected first two layouts (too dense). Settled on card-based approach. About to style individual cards. Key: react-day-picker, Supabase RPC, 3-col desktop / stacked mobile."

So the next session never starts cold.

## The Fundamental Unit

The fundamental unit is a PATTERN, not a data point.

Data point: "Max chose shadcn on May 6"
Pattern: "Max consistently chooses component libraries with Tailwind-native styling and copy-paste installation"

Data points don't make future sessions better. Patterns do.

## What Mirror Is

Mirror is a synthesis engine. It observes sessions, identifies patterns in decisions and process, and produces knowledge that makes the next session smarter.

The experience Max has WITH Mirror:
- Starts a new dashboard project → Claude already knows his dashboard process, preferences, quality bar → 40 messages instead of 150 → better result
- Picks up where he left off → context brief shows exactly where he was and what he was thinking
- Solves a hard problem → the solution pattern is available when a similar problem shows up in 3 months

The experience is: working with someone who's been on your team for 6 months, not a new hire every day.
